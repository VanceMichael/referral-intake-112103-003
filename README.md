# 院内转诊资料

本目录整理首诊、检查、跨科转诊和费用确认的合成记录，并提供可重复使用的
**转诊资料接收与跟踪能力**（`referral_tracker` 包）。每个来源保留就诊标识、
记录类别与生成时间，不包含真实患者信息。

## 能力说明

一次挂号后，首诊记录、检查报告、转诊流转、费用与号源记录从各自系统接入，
本能力负责：

- **幂等接入**：同一 `source_id` 只应用一次；同一报告/转诊的同一版本号出现
  不同内容时判为冲突并拒绝，避免相互矛盾的时间线。
- **复合身份**：患者身份、就诊号、转诊单号是三个独立字段
  （`ReferralKey`），同一次就诊可发往多个专科，互不混键。
- **跟踪查询**：每张转诊单可查到当前由谁接手（`owner`）、哪些依据仍未到齐
  （`missing_materials`）以及完整时间线。
- **版本化依据**：尚未接诊的转诊使用当前有效版报告；已接诊的转诊保留接诊时
  钉住的依据版本，接诊后报告更正会生成“需复核”提示。
- **结局纪律**：转诊被拒绝或患者未到诊记为未成交，不算成功完成，也不影响
  首诊已经完成的服务。
- **费用/号源闸门**：费用与号源只在对应环节被明确确认（如接诊确认）后才
  入账/占用，否则保持挂起；检查报告到达不会改变转诊状态。

## 角色与授权

| 角色 | 接入记录 | 查看视图 |
| --- | --- | --- |
| `records_clerk` | 全部类别 | 全部视图 |
| `coordinator` | 无 | 协调员/转诊/就诊视图 |
| `department_staff` | 本科室转诊、检查 | 仅本科室视图 |
| `cashier` | 费用记录 | 无 |

## 记录类别

`visit`（首诊）、`exam_report`（检查报告，按 `revision` 版本化）、
`referral`（转诊流转：`sent → accepted → completed`，或 `rejected` /
`no_show`）、`fee_receipt`（费用）、`slot_update`（号源占用申请，释放由
转诊结局自动派生）。

## 运行

使用 Python 3.11 或更新版本运行全部检查：

```sh
python3 -m unittest discover -s tests
```

接入合成演练数据并查看协调员/科室视图：

```sh
python3 -m referral_tracker
```

演练数据位于 `fixtures/sources.json` 与 `fixtures/drill_multi_specialty.json`。
项目不需要联网或第三方依赖。
